# BUG-010 — FKs sin ON DELETE CASCADE al borrar una cuenta

## Síntoma / causa raíz

Dos claves foráneas apuntan a `profiles`/`auth.users` **sin `on delete cascade`**:

- `public.appointments.cancelled_by`  (migración FEATURE-009)
- `public.reports.reviewed_by`        (migración FEATURE-011)

Si una cuenta llegó a **cancelar una cita** o **revisar un reporte** y luego se
intenta **borrar esa cuenta** (baja de usuario, borrado RGPD, limpieza de datos),
el borrado en cascada de `auth.users → profiles → …` se detiene con un
`foreign key violation` en esas dos filas.

Detectado en la auditoría de cierre (2026-07-25): el script de limpieza de datos
de prueba (`bdseed/seed_completo_borrar.sql`) tiene que **desvincular a mano**
esas dos columnas (`set … = null`) antes de borrar, justo por este hueco. Lo que
hace el script a mano debería hacerlo el esquema.

## Impacto

- **Bajas de cuenta / borrado RGPD**: hoy no hay una pantalla de "borrar mi
  cuenta" completa, así que el impacto en producción es latente; pero cualquier
  proceso de borrado de usuario (soporte, RGPD, limpieza) puede fallar.
- Riesgo de datos: workarounds manuales propensos a dejar entidades a medias.

## Solución propuesta

Migración que recree ambas FKs con la semántica correcta —probablemente
`on delete set null` (conservar la cita/el reporte pero desvincular al autor),
que es justo lo que hace el workaround del script—:

```sql
alter table public.appointments
  drop constraint appointments_cancelled_by_fkey,
  add constraint appointments_cancelled_by_fkey
    foreign key (cancelled_by) references public.profiles(id) on delete set null;

alter table public.reports
  drop constraint reports_reviewed_by_fkey,
  add constraint reports_reviewed_by_fkey
    foreign key (reviewed_by) references public.profiles(id) on delete set null;
```

(Confirmar los nombres reales de las constraints y la tabla/columna referenciada
antes de aplicar.)

## Solución (2026-07-25)

- Migración `20260725120000_bug010_fk_set_null.sql`: recrea
  `appointments_cancelled_by_fkey` y `reports_reviewed_by_fkey` con
  **`on delete set null`** (confirmados los nombres reales y que referencian
  `profiles(id)`).
- Test TDD `src/test/rls/borrado-cuenta.test.ts`: crea una cita cancelada por un
  usuario y un reporte revisado por otro, **borra esas cuentas** y comprueba que
  el borrado **no falla** y que `cancelled_by` / `reviewed_by` quedan en `NULL`.
  Rojo antes de la migración (el `deleteUser` devolvía error 500 por el FK),
  verde después.

## Criterios de aceptación

- Borrar una cuenta que canceló una cita o revisó un reporte **no falla**; esas
  filas quedan con el autor a `null`. Con migración + test. ✓
